## 0. 一句话结论

**SolidWorks 装配可以完全程序化**：零件插入、任意旋转、任意平移、解固定、存盘，全部用 COM 接口完成，不依赖鼠标拖拽。
**唯一做不到的是"几何配合（Mate）本身"** —— 本文用「直接写入每个组件的 4×4 变换矩阵」代替配合，精度到小数点后 3 位。

## 4. ★ COM 接口：能用的写法 与 必须避开的坑

### 4.1 附着到正在运行的 SW

```python
import pythoncom, win32com.client as w
pythoncom.CoInitialize()
app = w.GetActiveObject('SldWorks.Application')
doc = app.ActiveDoc            # 或遍历 app.GetDocuments 按 GetTitle 找
```
- `app.RevisionNumber`、`doc.GetTitle`、`app.GetProcessID`、`doc.EditRebuild3` 都是**属性，不能加 ()**
- `CO_E_SERVER_EXEC_FAILURE` 时不要用 `Dispatch` 拉起，**直接启动 exe 再附着**

### 4.2 插入零件 —— `AddComponent5` 是 **8 个参数**

```python
m = doc.AddComponent5(partPath, 0, "", False, "", x, y, z)   # x/y/z 单位：米
```
```
AddComponent5(CompName, ConfigOption, NewConfigName,
              UseConfigForPartReferences, ExistingConfigName, X, Y, Z)
```
- 少传第 5 个 `ExistingConfigName` → 报 `-2147352561 DISP_E_PARAMNOTOPTIONAL「非选择性的参数」`
- **新装配体必须先 `SaveAs3(dst, 0, 1)` 存盘拿到路径，才能插零件**，否则一律返回 None

### 4.3 ★ 设置组件姿态 —— 不要碰 `Transform2=` / `SetXform`

`IComponent2.Transform2` 的 **setter 只接受 `IMathTransform` 对象**，而 `IMathTransform` / `IMathUtility` 是自定义接口，pywin32 晚绑定解析不出方法（`GetMathUtility.CreateTransform` 必然失败）。

**更坑的是**：只要访问 `comp.SetXform` 这个属性名，就会触发一次无参调用、**把矩阵重置成单位矩阵**（我因此把零件扔到过原点）。

**唯一可靠写法**（`swasm.py` 里的 `set_mat`）：手工 `IDispatch::Invoke`：

```python
SAFE = pythoncom.VT_ARRAY | pythoncom.VT_R8

def set_mat(comp, data16):
    mt = comp.Transform2
    ole = mt._oleobj_
    dispid = ole.GetIDsOfNames('ArrayData')
    ole.Invoke(dispid, 0, pythoncom.DISPATCH_PROPERTYPUT, True,
               win32com.client.VARIANT(SAFE, list(data16)))
    comp.Transform2 = mt          # 必须写回组件才生效
```

### 4.4 ★ `ArrayData` 的 16 个数是什么顺序（实测确认，正交性误差 0）

```
[0..8]   3×3 旋转矩阵，行优先
         R[i][j] = 局部 j 轴在 世界 i 轴 上的分量
         局部 X 轴在世界中的方向 = R 的「第 0 列」= (a0, a3, a6)
[9..11]  平移 (Tx, Ty, Tz)，单位：米
[12]     scale（恒 1.0）
[13..15] padding（恒 0）
```

**写矩阵的模板**：设要让 `局部 X→世界 ?, 局部 Y→世界 ?, 局部 Z→世界 ?`，
把三个目标方向**按列**填进 3×3，再拼平移：

```python
R = [Rx[0], Ry[0], Rz[0],
     Rx[1], Ry[1], Rz[1],
     Rx[2], Ry[2], Rz[2]]
data = R + [Tx/1000, Ty/1000, Tz/1000, 1.0, 0.0, 0.0, 0.0]
set_mat(comp, data)
```
右手系必须满足 `Rx × Ry = Rz`（行列式 = +1），否则零件会镜像。

### 4.5 存盘

```python
doc.Save3(1, VARIANT_BYREF_I4, VARIANT_BYREF_I4)     # 返回 True
```
- `doc.Save3(1, 0, 0)` → 报 `-2147352571 类型不匹配`
- **不要**用 `SaveAs3` 存装配体（会改路径、断引用）

### 4.6 解固定

```python
comp.Select2(False, 0)      # 不能用 Select4（类型不匹配）
doc.UnfixComponent()        # 不是 Component2.Unfix
```

### 4.7 3D Interconnect（导入 STEP 必踩）

- 导入 STEP 会生成 `%TEMP%\swx####\IC~~\xxx.stp.SLDPRT` 这样的链接文档，**这种组件官方禁止浮动**
- 关闭：`doc.Extension.SetUserPreferenceToggle(691, False)`（691 = `swMultiCAD_Enable3DInterconnect`）
- 关掉后重新导入才是真转换实体

### 4.8 截图

```python
doc.ShowNamedView2('*Isometric', 7)     # 必须作用在 app.ActiveDoc 上，不能用 OpenDoc6 的返回值
doc.ViewZoomtofit2()
doc.SaveBMP(path, 2400, 1800)           # 必须传宽高
```
视图名/ID：`*Front`1 `*Back`2 `*Left`3 `*Right`4 `*Top`5 `*Bottom`6 `*Isometric`7

**只显示局部要截的零件**（不然 zoomtofit 框整个装配，目标缩成一点）：
```python

app.ActiveDoc.ActiveView.DisplayMode = 5      # 1→5 刷新渲染缓存，否则全是线稿
```

### 4.9 从类型库查真实签名（猜不出来时用这个）

```python
import pythoncom
lib = pythoncom.LoadTypeLib(r'<SW安装目录>\sldworks.tlb')
for i in range(lib.GetTypeInfoCount()):
    ti = lib.GetTypeInfo(i)
    if ti.GetDocumentation(-1)[0] != 'IAssemblyDoc': continue
    k = 0
    while True:
        try: fd = ti.GetFuncDesc(k)
        except Exception: break
        k += 1
        names = ti.GetNames(fd.memid)      # names[0]=函数名, names[1:]=参数名
```
参考实现：`read_tlb_func.py`

## 5. ★ 几何分析（OCP / OpenCASCADE）要点

### 5.1 两个致命陷阱

1. **不要用 `cylinder.Axis().Location()` 当孔的位置**
   那个点对部分面是任意参数化点，会跑到零件外面（我因此得到过 X=±79 的假坐标，零件本身只有 ±22）。
   **正确做法：用面的 `Bnd_Box` 中心**：
   ```python
   bb = Bnd_Box(); BRepBndLib.AddOptimal_s(face, bb, True, False); b = bb.Get()
   center = ((b[0]+b[3])/2, (b[1]+b[4])/2, (b[2]+b[5])/2)
   ```

2. **只扫圆柱面会漏掉方孔/异形孔/半圆缺口**
   必须补一次**平面分析**：统计所有 `GeomAbs_Plane` 面的法向+位置+面积，
   用「端面面积缺口」反推孔轮廓。侧盖的 U 形槽结构就是这么找出来的
   （Y=0 面比外形少 183.78，Y=2 面同样少 183.78 → 贯穿缺口）。
   参考：`geo_faces.py`

### 5.2 STEP 单位

STEP 本身就是**毫米**，不要再乘 1000。

### 5.3 判断两个孔是否同轴

```python
def line_dist(p1, d1, p2, d2):   # 两无限直线最短距离；再算方向夹角
```
同轴 ⟺ **距离 ≈ 0 且 夹角 ≈ 0°**。
**距离≈0 但夹角 90° = 两轴正交交叉，视觉上"差不多重合"，但不是同轴**——这是最容易误判的情况，见 §7。

## 7. 当前装配状态 与 卡住的地方（重点看这段）

### 7.1 已完成
- `装配体_重建.SLDASM`：24 个顶层实例，6×4 网格摊开，只有 `12_tube_al_L80-1` 固定
- 侧盖 `双轴侧盖-3`：**(1312.33, 57.70, 1200.00)，单位矩阵**（平放、立板朝上、中心孔对正圆柱轴）
- M2 `HTD-45H-2`：**T=(1308.52, 72.42, 1174.13)，R=[0,1,0, -1,0,0, 0,0,1]**
  - 即 `局部Y→世界X, 局部Z→世界Z, 局部X→世界-Y`
  - 世界包围盒 X[1292.3,1332.3] Y[62.7,82.8] Z[1173.7,1226.3]
  - **输出轴沿世界 Z（水平）**，机身 40.04 卡进立板内间距 40.00（单侧余量 -0.02mm）
  - M2 底面 Y=62.70，距侧盖板面 59.70 留 **3.0mm 间隙（这个值是我暂定的，需用户确认）**

### 7.2 ★ 卡住的问题：螺丝孔对不上

用户要求「M2 的螺丝孔和侧盖立板孔精准对齐，两边都要对」。实测结论：

- 立板孔 **轴沿世界 X** 横向穿板
- M2 的 4 个安装孔 **轴沿自身 Z**；由于要求输出轴沿世界 Z，这 4 个孔也就 **沿世界 Z**
- 两者 **恒为 90°**，逐孔配对算出的最短轴线距离 **0.057~0.075mm**（用户看到的"差不多对齐"就是这个），
  但**夹角一律 90°** —— 是正交交叉，不是同轴
- M2 侧壁上没有 φ2 孔，所以"螺丝横向穿立板进舵机侧面"这条路在**这个模型上不成立**

**硬约束**：`输出轴沿世界 Z` ⟺ `安装孔沿世界 Z` ⟺ `与立板孔垂直`。二者不可兼得。

**可选解法（需用户拍板）**
- **A**：M2 绕 Y 转 90°，输出轴改沿世界 X（左右水平）→ 4 个孔沿 X，能穿立板
- **B**：保持输出轴水平沿 Z，靠 U 形槽两侧夹持定位，不穿螺丝
- **C**：按实物舵机的侧面孔位，在 HTD-45H 模型上**手工开孔**，再对到立板孔（需要用户提供实物孔位置）

## 8. 用户口述的装配关系（原话要点）

- M1 / M2 / M3 都用 **HTD-45H 外形**的双轴舵机
- **M1 装在圆柱体里面 → 已省略**，模拟时只要求"侧盖能相对底下圆柱绕世界 Y 轴转动"

- M2 底面与侧盖之间**有一点间距**
- 侧盖底面紧贴零件76 顶面；侧盖中心孔与圆柱同心共轴，可绕 Y 转
- 侧盖两条立板上的螺丝孔要与 M2 外壳螺丝孔对齐
- 长U支架装在 M2 舵盘上，两边螺丝孔都要对，然后转到水平约 80 多度

## 9. 直接可复用的代码

```python
import sys; sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))  # swasm.py 所在目录
import swasm

app  = swasm.get_app()                    # 附着 SW
doc  = swasm.find_asm(app, '装配体_重建')  # 激活并返回装配体
comp = swasm.find_comp(doc, 'HTD-45H-2')  # 按名字前缀找组件
print(swasm.pos_mm(comp))                 # 当前位置(mm)
swasm.set_mat(comp, data16)               # 写入 4x4 矩阵
doc.Save3(1, swasm.byref0(), swasm.byref0())
```
