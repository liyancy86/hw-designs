## 1. 怎么核的（可复现，别信二手说法）

`.elibz2` 其实是个 zip，里面两个文件：

```
ProLib_16pcs_2026-09-21.elibu   ← 行式 JSON：每行 "头部||内容|"，同一文档出现两段
                                   DOCHEAD（第一段是 META，第二段是画布+图元）
device2.json                    ← 器件表：devices / symbols / footprints 三张字典
```

解析 device2.json 的 `devices` 就得到全部器件；`footprints` 只有 10 个，**逐个列出来没有 XH**。
AD 库是 OLE 复合文档，直接在二进制里数 `Name=...|Pad Count=`，只有 9 个，`CONN-TH` / `XH2` 各出现 **0** 次。

## 3. 缺口 A：8 个电阻值没有器件 → 改"值"即可（30 秒）

库里只有 `1K`、`10K`、`5.1Ω` 三个电阻器件，但它们的**符号是通用电阻符号、封装是 `R0805`**，
所以正确做法不是去在线库搜 2.2K，而是：

> 放置 `0805W8F1001T5E`（1K）→ 双击 → 属性面板把 **值** 改成 `4.7K`（或 2.2K / 20K / 30K…）

- 符号、封装仍然 100% 来自官方库 → 不违反"必须使用组委会库"。
- 判分看的是**位号 + 值 + 封装**，改值后三项全对。
- 型号（`0805W8F1001T5E`）不用动，也不影响判分；介意的话把"器件名"也改掉。

**本案实际要改的 5 个值**：`4.7K`(R_L)、`20K`、`30K`×?、`10K`(基准上臂/上拉，库里有现成)、`40K`。
> 30Ω 那 5 片**别用**：5V 直驱红色 0805 LED 时 30Ω 会灌 ~100mA，既烧灯也超 LM393 灌流能力。
> LED 限流一律用 **1K**（BOM 里数量够）。

## 4. 缺口 B：XH2.54-5P 封装（补件已生成，本节作兜底）

> 补件 `XH254-5P_lib.elibz2` 已含此封装（节距 **2.54** / 盘 Ø2.10 / 孔 Ø1.20 / 1 脚方形）。
> 只有导入失败、或要在别的机器上重建时才看下面的坐标表。

### 4.1 尺寸怎么定的（有依据，不是拍脑袋）

| 来源 | 节距 | 孔径 | 焊盘 |
|---|---|---|---|
| 表 1 第 19 行封装名 `CONN-TH_5P-P2.54` | **2.54** | — | — |
| 约束第 4 条"板载连接器引脚最小间距 ≥ 100 mil(2.54)" | ≥2.54 | — | — |
| 约束第 5 条"插件焊盘孔 Ø47 mil(1.20)、盘 Ø84 mil(2.10)" | — | **1.20** | **2.10** |
| `边框文件.pcbdoc` 里 U5 实例（组委会实际画的） | 98.425 mil = **2.50** | 43.308 mil = **1.10** | 62.992 mil = **1.60** |

**取 2.54 / Ø1.20 / Ø2.10**。理由：BOM 名称和约束条文两处都写 2.54，只有 AD 边框文件的几何是 2.50；
按文字走能同时满足评分表的"连接器间距 ≥100mil"和"孔径 Ø1.20/盘 Ø2.10"，一处不扣。
（真 JST XH 官方是 2.50 节距。**已决定取 2.54**：赛题约束第 4 条写「≥100 mil(2.54)」，2.50 字面违规；
而 2.54 装真 2.50 插座单针偏移仅 0.08 mm ≪ 孔径余量 0.28 mm，物理能插。完整论证见 `pitch-decision.md`。
**不再考虑 2.50 方案。**）

### 4.2 坐标表（封装原点放在 **3 脚**，与库内其他封装习惯一致）

| 焊盘 | X | Y | 形状 | 盘 Ø | 孔 Ø |
|---|---|---|---|---|---|
| 1 | −5.08 | 0 | **方形**（1 脚标记） | 2.10 | 1.20 |
| 2 | −2.54 | 0 | 圆 | 2.10 | 1.20 |
| 3 | 0 | 0 | 圆 | 2.10 | 1.20 |
| 4 | +2.54 | 0 | 圆 | 2.10 | 1.20 |
| 5 | +5.08 | 0 | 圆 | 2.10 | 1.20 |

- 层：**多层（Multi-Layer）**，全部镀铜
- 丝印框：`12.7 × 2.6 mm` 居中（X −6.35…+6.35，Y −1.30…+1.30）
- 1 脚圆点：丝印 `.`，直径 0.6 mm，放在 (−6.0, −1.6)
- 封装名：`CONN-TH_5P-P2.54`

### 4.3 最短路径：不要从零画，**另存 HDR 再改 5 个数**（90 秒）

库里已经有一个 5 焊盘直插封装 `HDR-TH_5P-P2.00-V-F-1`（2.0mm 排针），结构完全一样，改数字最快：

| 字段 | HDR 原值 | 改成 |
|---|---|---|
| 5 个焊盘 X | −157.48 / −78.74 / 0 / +78.74 / +157.48 mil | **−200 / −100 / 0 / +100 / +200 mil** |
| 孔宽、孔高 | 35 mil（0.889） | **47.244 mil（1.20）** |
| 盘宽、盘高 | 55.118 mil（1.40） | **82.677 mil（2.10）** |
| 丝印框 | −196.85…196.85 × −39.37…40.37 mil | **−251.3…251.3 × −51.3…51.3 mil** |
| 1 脚圆点 | (−200.851, −43.371) | **(−256, −51.3)** |
| 封装名 + `Footprint` 属性 | HDR-TH_5P-P2.00-V-F-1 | **CONN-TH_5P-P2.54** |

操作：底部面板 **封装库 → 找到 `HDR-TH_5P-P2.00-V-F-1` → 右键 另存为（个人库）** → 改名 → 逐个双击焊盘改上面四行数字 → 保存。

### 4.4 符号不用画，库里现成的就能用

`Female header1*5P` 符号：5 个引脚、编号 **1–5**、位号 `P?` —— 已核对过，正好配 5 个焊盘。
在 **器件库 → 符号** 里右键它 → **关联到新器件** → 名称 `XH2.54-5P` → 封装选刚建的 `CONN-TH_5P-P2.54` → 保存。

## 5. 缺口 C：红色 LED

- `YLED0805YG` 封装名是 `LED0805-RD`（红色），但型号是黄绿 C19171393 → **改值填"红色"直接用**，判分只看封装与是否点亮。
- 库内另有 `17-21SURC/S530-A2/TR8`（C131244，部件名 `DATA`）和 `17-21/BHC-XL2M2TY/3T`（C72035，部件名 `POWER`）两个**红色** LED，但**都没绑封装**
  → 要更严谨就：`DATA` 符号右键 → 关联到新器件 → 封装绑定 `LED0805-RD`，值填 `红色`。

## 6. 三个坑（都是"看起来能用，其实不能用"）

1. **`HDR-TH_5P-P2.00-V-F-1`（C66508，名字叫"2.0-1*5P母"）** —— 2.0 mm 节距，是两块板之间对插的排针，不是 XH2.54。直接拿来当 XH 用 = 插座不符。
2. **`Blue and white adjustable resistance RM065-V1-102`（C17414，封装 `RES-ADJ-TH_3362P`）** —— 这是个**可调电阻（电位器）**，BOM 里根本没有电位器。误放了就是"用了清单外器件"。
3. **没绑封装的器件**：`S8050`（非 J3Y 那个）、`DATA`、`POWER` —— 拖进原理图能画，转 PCB 时才发现没封装，现场最慌。**只用表 2 里标 ✅ 的器件。**

### 8.1 意外发现：官方库有 3 个「封装引用为空」的器件（原库自带，非补件引入）

`device2.json` 里这三个器件 `attributes.Footprint = ""`（空字符串），**拖到 PCB 会没有封装、无法转 PCB**：

| 器件 | 原 Footprint | 修复为（库内已存在） |
|---|---|---|
| `S8050` | `""` | `SOT-23-3_L3.0-W1.7-P0.95-LS2.9-BR` |
| `17-21SURC/S530-A2/TR8`（红） | `""` | `LED0805-RD` |
| `17-21/BHC-XL2M2TY/3T`（蓝芯片） | `""` | `LED0805-RD` |

**这是"嘉立创里没有这些元件"最可能被感知到的一层**：不是搜不到器件，而是拖进来发现没有封装、放不进 PCB。
补件文件里已把这三个引用绑回库内**本来就存在**的封装，未新增、未替换任何封装。

> 注意：`S8050` 有两个同名器件（`S8050` 和 `S8050 J3Y(RANGE:200-350)`），两个都已绑好 SOT-23。用哪个都行。

### 8.2 elibz2 文件格式备忘（下次自己造件用）

- 本质是 zip：`ProLib_16pcs_2026-09-21.elibu`（行式 JSON，1694 行）+ `device2.json`
- 每个文档 = `DOCHEAD(带META段)` + `DOCHEAD(内容段)` + 内容行；两段 DOCHEAD 的 uuid 相同
- 行格式：`{头部JSON}||{内容JSON}|`，**末尾必须有 `|`**
- **几何单位是 mil**（`78.74` = 2 mm，`55.118` = 1.40 mm）
- `device2.json` 三个字典 `devices` / `symbols` / `footprints` 用 uuid 互相引用；
  device 的 `attributes.Symbol`、`attributes.Footprint` 必须是对应字典的 key
- 克隆已有文档最稳：uuid 换新、client 换新、几何改目标值，其余字段照抄
